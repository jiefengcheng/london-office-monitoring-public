# Shared London evidence contract v0.1

The Python gateway implements five logical, read-only tools in `agent_tools.py`, using only the standard library. The input/output schemas are in [tool-contract.json](tool-contract.json), the allowed cross-section group is in [cross-section-groups.json](cross-section-groups.json), and [golden-cases.json](golden-cases.json) provides portable request/response examples. Changes to the shared tool interface require a contract version update and regression checks.

| Tool | Arguments | Result |
|---|---|---|
| `search_facts` | Optional `topic`, `metric`, `geography`, `entity`, `period_start`, `period_end`; bounded `limit` | Matching complete fact records, truncation flag and explicit scope/match semantics |
| `get_fact` | `fact_id` | One complete joined fact/source record or `NOT_FOUND` |
| `compare_facts` | `fact_id_a`, `fact_id_b`, `mode` (`time_series` default; `cross_section` explicit) | Inputs, deterministic difference/unit, pp/bps or relative change as applicable, rounding caveat; or `COMPARISON_REFUSED` |
| `get_source` | `source_id` | Original source metadata and associated fact IDs; fact-specific locators come from fact records |
| `coverage_gap` | `request` plus optional `topic`, `metric`, `geography`, `entity`, periods | Relevant coverage rows, available evidence and explicit missing/ambiguous scope; never infer absence beyond fixture coverage |

Use an envelope `{"contract_version":"0.1","ok":true,"data":...,"error":null}`. Failures use `ok:false`, `data:null`, and `error:{"code":...,"message":...}`. Codes include `INVALID_ARGUMENT`, `NOT_FOUND`, `COMPARISON_REFUSED`, `EVIDENCE_UNAVAILABLE`. Empty search results are valid empty results, not evidence of zero market activity. Unknown tools, extra arguments, malformed dates and unbounded limits are rejected. No tool accepts SQL or fixture paths.

Python callers may use the five named functions or `invoke(tool_name, arguments)`. CLI: `python3 agent_tools.py TOOL --field-name VALUE`, or use `--arguments-json` with one JSON object instead of flags. Results go to stdout as JSON; success exits 0, all error envelopes exit 2. `--help` is ordinary CLI help. Duplicate JSON keys, nonfinite JSON constants and mixed JSON/individual flags are rejected. No dependency installation, API key or network access is needed.

`topic` is a canonical lowercase enum. `metric` and `geography` use exact ASCII-case-insensitive equality; geography never expands to a wider label or alias. `entity` is a literal ASCII-case-insensitive substring: SQL wildcard characters retain their literal meaning. Date filters are inclusive interval overlap on the stored observation/target interval, not publication date. Omitted filters remain unconstrained. Optional fields are omitted, not null. Dates must be canonical YYYY-MM-DD, bounds ordered, and nonblank strings within schema limits.

Search defaults to 20 results, allows integer limits 1–100, orders by `fact_id`, and reports `count` for returned facts plus `truncated`. It does not report a total-match count. Facts retain every original field and joined provenance; nested `source` adds the complete original source record, including access status, role and limitations. `get_source` returns that original metadata plus sorted `fact_ids`; optional sources can legitimately have none.

Preserve all fact fields and joined source provenance: fact/source IDs, original publisher geography and basis, segment, metric, value/unit, period kind/start/end, status/evidence class, publication/retrieval dates, source URL, locator, caveat and curated series key. Retain optional-source access qualifications. Do not treat reference answers as source evidence.

Runtime opens SQLite with `mode=ro` and `PRAGMA query_only=ON`; all variable predicates are parameters. The gateway reuses supplied `get_fact()` and `compare_facts()` for time-series mode. Differences/basis points are plain decimal strings without insignificant trailing zeros. Relative growth is rounded to one decimal place in percent with half-even rounding, marked `relative_change_approximate:true`, and retains the reported-values caveat. Percentage-valued series produce percentage-point differences, not relative percent growth. Reversed time inputs remain ordered chronologically; cross-section always means `b_minus_a`. No fixture JSON or chat oracle is loaded at runtime.

`cross_section` is separate: require same metric, unit, period, publisher, geography basis, segment, evidence class and comparable numeric statuses, and an explicitly approved comparison group. Do not weaken the time-series comparator's curated-series rule. F09/F10 need an approved same-period City/West End comparison; expected West End minus City is GBP 29.96/sq ft. Range values and forecasts remain refused. Tests must include sign/order behavior.

Coverage assessment is `matching_facts_in_fixture`, `no_matching_facts_in_fixture` or `needs_scope`. It requires topic, metric, geography and both period bounds before establishing a fixture gap. The only complete prose convenience form is `<publisher geography> vacancy|availability [rate] [in] Qn YYYY`, optionally followed by `?`. Other prose, conflicts and multiple scopes require clarification; supported keyword hints may still select coverage rows and partially filtered fact IDs. Explicit structured filters can supply the full scope with a context-only request. Availability is never converted to vacancy. When no topic can be resolved, all coverage rows remain available for inspection; an unknown explicit topic is rejected. Available IDs are bounded at 100 with `truncated`; with unresolved scope they are partial matches, not a supported answer. All absence statements are limited to this curated fixture.

`contract_validation.py` validates the vocabulary used by these schemas, including local `$defs`, strict object shapes, oneOf, types, bounds, enums, patterns and canonical date formats. It is not a general-purpose JSON Schema engine and never loads model-supplied schemas or remote references. Each tool's `parameters` and `response` definitions share the top-level `$defs`.

The schemas and golden examples are checked by deterministic tests for arithmetic, refusals, scope and source provenance. The separate `agent-answer.schema.json` defines which observed evidence references a provider may select; Python validates those references and renders the final response. Keep evaluation expectations outside runtime prompts and credentials outside traces.
